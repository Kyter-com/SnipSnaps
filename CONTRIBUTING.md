# Contributing to SnipSnaps

Thanks for helping improve SnipSnaps. Bug reports, feature ideas, documentation
improvements, tests, and focused code changes are welcome.

## Before you start

- Open an issue before a large feature or architectural change so the approach
  can be discussed.
- Keep pull requests focused on one concern.
- Do not include private data, credentials, copyrighted assets you cannot
  license, or code copied from incompatible sources.

## Development

Open `SnipSnaps.xcodeproj`, select the `SnipSnaps` scheme, and run it on an
iPhone, iPad, or Mac destination.

When submitting a change:

- follow the existing Swift and SwiftUI style;
- include or update tests when practical;
- verify the relevant app destination still builds; and
- add a Changeset for user-facing changes.

## Contribution terms

SnipSnaps is distributed under the [MIT License](LICENSE). By submitting a pull
request or other contribution, you agree that your contribution will be
licensed under the same terms.

You must own the work or have permission to submit it. If your employer or
another organization owns the work, obtain its permission before contributing.

## Security

Do not open a public issue for a security vulnerability or sensitive report.
Use the private contact path on the
[SnipSnaps support page](https://kyter.com/snipsnaps/support/).
